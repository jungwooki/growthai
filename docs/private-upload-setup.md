# 비공개 원본 직접 업로드 — 1단계

> **현재 프로젝트 설정:** 새로운 AWS 경험, 리전 `ap-southeast-2`, 로컬 CLI 프로필 `growthai`. 비공개 S3 생성과 실제 12개 파일 업로드·앱 읽기 검증을 완료했습니다. Vercel 운영 연결과 배포는 미완료입니다. AWS 관리 정책이 OIDC 제공자 관리를 차단하여 다음 결정이 필요합니다. [설정 및 검증 기록](aws-connection-status.md)을 참고하세요. 아래 장기 키 방식은 기존 AWS 환경용 참고 자료이며 현재 프로젝트에 적용하지 않았습니다.

## 구현 상태 (2026-09-26)

이미지 직접 업로드 및 Vercel 요청별 OIDC 인증 코드는 구현되었습니다. **실제 S3 검증은 완료했고, Vercel 역할 인증 설정과 운영 배포는 남아 있습니다.**
환경변수를 모두 설정해야 `/api/status`의 `upload_mode`가 `s3`로 바뀝니다.
설정이 없으면 기존 방식(Vercel 첨부 합계 4MB)을 유지합니다.
`upload_mode=s3`는 설정값 존재 여부이며, 실제 연결 성공 여부는 업로드로 확인해야 합니다.

- 한 검사당 추가자료 포함 최대 12개, 파일당 20MiB, 합계 240MiB.
- 척골·요골·대퇴골 각 3–4장으로 9–12장을 기본 구성합니다. 부위별 최대 5장, 전체 최대 12개입니다.
- JPG, PNG, WEBP 및 추가자료 PDF/UTF-8 TXT. **동영상·DICOM은 아직 지원하지 않습니다.**
- 브라우저 → 비공개 S3에 원본 그대로 업로드 → 서명된 파일 목록만 평가 API로 전송.
- 업로드 진행률, 실패 시 최대 3회 시도. 같은 화면에서 다시 요청하면 성공한 파일을 재사용합니다.
- 업로드 허용 시간 15분, 판독 요청용 목록 유효기간 1시간. 재개 가능한 영상 multipart 업로드와는 다릅니다.
- 서버에서 파일 수·크기·형식·SHA-256·로그인 세션을 검증합니다. S3 정책도 크기·체크섬·MIME을 고정합니다.
- 저장 경로는 `exams/<무작위 검사 ID>/<무작위 파일 ID>.<확장자>`입니다. 환자 이름·원래 파일명은 경로에 넣지 않습니다.
- 저장된 원본은 변경하지 않습니다. 기존 AI 입력용 이미지의 최대 긴 변 1,800 변환은 유지합니다. **원본 전체 해상도를 AI가 읽는 구현은 아닙니다.**
- JSON 결과에 검사 ID, 원본 key, 크기, 체크섬을 포함합니다. 환자별 보관함·이력 검색·원본 다운로드 화면은 후속 단계입니다.
- 새로고침하면 입력·업로드 티켓은 사라지지만 S3 원본은 남습니다. 업로드 후 평가가 실패해도 원본은 남습니다.

## 사용자가 설정할 내용

### 1. AWS S3 비공개 버킷

[S3 콘솔](https://s3.console.aws.amazon.com/s3/home)에서 일반 버킷을 생성합니다.

- 리전: 시드니 `ap-southeast-2`.
- 버킷명: 다른 계정과 겹치지 않는 영문 이름. 환자 정보는 넣지 않습니다.
- **퍼블릭 액세스 차단 4개 모두 활성화**, ACL 비활성화(Bucket owner enforced).
- 기본 암호화: Amazon S3 관리형 키(SSE-S3).
- 버전 관리는 이번 단계에서 필요하지 않습니다. 켜면 동일 원본 재시도 시 버전별 용량이 쌓일 수 있습니다.
- 파일 보존·삭제 기간은 운영 정책에 맞게 정합니다. 코드에 자동 삭제는 없으며, S3 수명 주기를 설정하지 않으면 계속 보관됩니다. 먼저 가상 자료로 검증합니다.

스토리지 용량·요청·전송에 AWS 사용료가 발생합니다. 사용자 요청에 따라 실제 비공개 버킷을 생성했습니다. 중복 생성하지 말고 설정 기록의 버킷을 사용하세요.

버킷 → **권한 → CORS**에 다음을 입력합니다. 운영 주소가 바뀌면 정확한 주소를 추가합니다. 임의의 모든 웹사이트를 허용하지 않습니다.

```json
[
  {
    "AllowedOrigins": ["https://growthai-two.vercel.app"],
    "AllowedMethods": ["POST"],
    "AllowedHeaders": ["*"],
    "MaxAgeSeconds": 300
  }
]
```

### 2. 업로드 전용 IAM 권한

전용 IAM 사용자/키에 아래 정책을 적용합니다. `YOUR_BUCKET_NAME`을 1단계 버킷명으로 바꿉니다.
루트 계정 액세스 키는 사용하지 않습니다. 이 앱에는 버킷 관리·목록·삭제 권한이 필요하지 않습니다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/exams/*"
    }
  ]
}
```

### 3. Vercel 환경변수

Vercel → growthai 프로젝트 → Settings → Environment Variables → Production에 다음을 입력합니다.

| 이름 | 값 |
| --- | --- |
| `MEDIA_STORAGE` | `s3` |
| `MEDIA_S3_BUCKET` | 생성한 버킷명 |
| `MEDIA_S3_REGION` | `ap-southeast-2` |
| `MEDIA_AWS_ACCESS_KEY_ID` | 전용 IAM 액세스 키 ID |
| `MEDIA_AWS_SECRET_ACCESS_KEY` | 해당 시크릿 액세스 키 |
| `MEDIA_SIGNING_SECRET` | 독립적인 무작위 비밀값, 최소 32자 |

비밀값은 채팅·GitHub·스크린샷에 올리지 말고 Vercel의 비밀 환경변수로 직접 입력합니다.
Python이 있는 로컬 터미널에서 `py -c "import secrets; print(secrets.token_urlsafe(48))"`로 서명용 값을 생성할 수 있습니다.
Preview를 사용할 경우 환경변수와 CORS에 해당 Preview 주소도 별도로 설정합니다.
기존 로그인 및 `OPENAI_API_KEY` 설정은 그대로 필요합니다.

## 코드 배포와 실제 연결 검증

1. 이 변경 사항이 포함된 코드를 GitHub 배포 브랜치에 반영한 후 Vercel을 재배포합니다. **설정만 저장하거나 이전 코드를 재배포하면 적용되지 않습니다.**
2. 로그인한 평가 화면에서 합계 한도가 `240MB`, 비공개 원본 보관 안내가 표시되는지 확인합니다.
3. 개인 정보 없는 가상 이미지 12장(합계 4MB 초과)을 각 부위에 4장씩 넣고 AI를 끈 상태로 요청합니다.
4. 파일별 업로드 → 결과에 자료 12개가 표시되는지 확인합니다. S3 객체 수·크기와 JSON의 원본 key·체크섬을 대조합니다.
5. 네트워크를 끊었다 복구하여 재시도를 확인합니다. 저장소 오류에는 4MB 방식으로 자동 우회하지 않습니다.
6. 원본의 익명 브라우저 접근이 차단되는지 확인합니다. CORS는 인증을 대신하지 않습니다.
7. 참고자료와 AI 키가 준비된 환경에서 실제 판독 연결을 별도로 확인합니다. 로컬 가상 테스트는 실제 AWS CORS/IAM 또는 AI 판독 정확도를 검증하지 않습니다.

설정이 완성되지 않으면 기존 4MB 제한이 표시됩니다. 403 업로드 오류는 IAM·CORS·리전·서명 만료를, 체크섬 오류는 파일 변경 여부를 확인합니다.
긴 PDF/여러 큰 이미지의 실제 처리 시간은 촬영 파일로 측정해야 합니다. 기존 Vercel 함수 실행 시간 제한과 AI 비용은 유지됩니다.

## 검증 기록

- Python 테스트: 12장/4MB 초과 자료 연결, 위변조·만료·다른 세션·가짜 파일 형식·용량 초과 거절 및 기존 기능 회귀 검증.
- JavaScript 테스트: 실패 파일 재시도, 완료 파일 재사용, 원본 파일명 대신 고정 업로드 파일명, 메타데이터만 API에 전송.
- 브라우저: 가상 저장소를 통해 4.6MiB/12장 입력 → 직접 업로드 → 기본 평가 결과 12개 표시 확인. AI 호출 없음.
- 실제 S3: 합성 이미지 12개 / 4,813,332바이트 업로드 → 앱 읽기 → 기본 평가 결과 12개 확인. CORS, 익명 접근 차단, 크기·체크섬 위반 차단 통과. 테스트 객체만 삭제했습니다. AI 호출은 하지 않았습니다.
- **운영 배포 및 배포된 Vercel에서의 OIDC 인증 검증은 미완료입니다.**

## 후속 단계

동영상 원본 multipart/resumable 업로드, 프레임 추출 작업, 촬영 시각·부위별 추적, 영상 판독 연결 및 처리 시간 관리.
이전 제안의 영상 250MB·검사 전체 1GB는 아직 적용된 제한이 아닙니다.
